# 한국관 POS (태블릿 전용 앱)

주방 프린터 **자동 인쇄**를 위해 만든 안드로이드 앱입니다. 화면에 보이는 건
지금 쓰시던 관리자 페이지 그대로고, 달라지는 건 인쇄가 나가는 방식뿐이에요.

## 왜 이 앱이 필요했나

크롬에서는 "신규 주문 자동 인쇄"가 절대 동작할 수 없었어요. 자동 인쇄는 4초마다
도는 타이머에서 실행되는데, **안드로이드 크롬은 사람이 직접 누르지 않은 상태에서
웹페이지가 다른 앱(RawBT)을 실행하는 걸 차단**하기 때문이에요. 광고 악용을 막는
크롬 자체 정책이라 어떤 API로도 우회할 수 없어요. 수동 인쇄 버튼은 진짜 클릭이라
통과했고, 자동은 조용히 무시됐던 게 이 차이 때문입니다.

이 앱 안에서는 그 정책이 적용되지 않아요. 게다가 **RawBT도 이제 필요 없습니다** —
앱이 프린터의 IP·포트(9100)로 직접 연결해서 인쇄 데이터를 보내기 때문이에요.
중간에 글자를 다시 해석하는 단계가 없으니 한자가 깨질 여지도 사라집니다.

```
크롬:   페이지 → rawbt: 링크 → [클릭 없으면 차단] → RawBT → 프린터
이 앱:  페이지 → 앱이 가로챔 → 프린터로 직접 (TCP 9100)
```

## 설치 방법

1. `hangukgwan-pos-1.0.apk` 파일을 태블릿으로 옮깁니다 (카톡·구글드라이브·USB 무엇이든)
2. 파일 관리자에서 APK를 탭하면 "출처를 알 수 없는 앱" 허용을 물어봅니다 → 허용
3. 설치 후 홈 화면에 빨간색 **한국관 POS** 아이콘이 생깁니다

## 처음 실행할 때 설정

앱을 처음 열면 설정 화면이 뜹니다. 세 가지를 입력해주세요.

| 항목 | 값 |
|---|---|
| 관리자 페이지 주소 | 지금 크롬에서 쓰시는 관리자 페이지 주소 그대로 |
| 프린터 IP 주소 | 공유기에서 확인한 프린터 IP (예: `192.168.1.50`) |
| 프린터 포트 | `9100` (그대로 두시면 됩니다) |

**"프린터 테스트 인쇄"** 버튼을 먼저 눌러보세요. 영수증이 한 장 나오면 프린터
연결이 정상입니다. 안 나오면 화면 아래에 실패 원인이 표시돼요.

그 다음 **"저장하고 시작"** → 관리자 페이지가 열립니다. 로그인은 기존 관리자
비밀번호 그대로예요.

> 프린터 IP는 공유기에서 **고정(DHCP 예약)** 해두세요. 안 그러면 IP가 바뀌면서
> 어느 날 갑자기 인쇄가 끊깁니다.

## 사용법

평소처럼 쓰시면 됩니다. 다만 **"신규 주문 자동 인쇄" 체크박스는 한 번 켜두세요.**
(이제 새로고침해도 꺼지지 않고 유지됩니다.)

- 설정을 다시 열려면: **화면을 손가락 세 개로 1초간 길게 누르세요**
- 인쇄가 실패하면 화면 아래에 그 이유가 잠깐 표시됩니다
- 앱이 켜져 있는 동안은 화면이 자동으로 꺼지지 않습니다

## 업데이트

관리자 페이지 내용(메뉴, 화면, 기능)은 **앱을 다시 설치할 필요가 없어요.**
지금까지처럼 코드 고치고 push하면 그대로 반영됩니다. 이 앱은 그 페이지를 띄우는
창틀일 뿐이라서요.

앱 자체(아이콘·이름·인쇄 로직)를 바꿀 때만 새 APK를 만들어 덮어 설치하면 됩니다.
기존 앱을 지울 필요 없이 그냥 설치하면 돼요. **단, 서명키(`keystore/hangukgwan.jks`)가
반드시 같아야 합니다** — 키가 다르면 "기존 앱과 서명이 다르다"며 설치를 거부해요.
이 파일을 잃어버리면 앱을 지우고 새로 설치하는 수밖에 없으니 잘 보관해주세요.

## 빌드 방법 (개발용)

구글의 안드로이드 SDK 서버가 막힌 환경에서도 빌드되도록, 필요한 도구 네 개만
`/opt/andtools`에 두고 Gradle 없이 직접 빌드합니다.

```bash
./build.sh                                   # 사이드로드용 APK
VERSION_CODE=3 VERSION_NAME=1.2 ./build.sh   # 버전 올릴 때

./build-aab.sh                               # Play 업로드용 .aab
```

Play 스토어(내부 테스트) 출시 절차와 각종 설문 답변은 **`PLAY-RELEASE.md`** 에 정리돼
있습니다. 신규 앱은 API 36을 타겟해야 해서 `TARGET_SDK=36` 으로 맞춰져 있고, 그에 따라
Android 15+ 의 edge-to-edge 표시를 위해 시스템 바 영역만큼 여백을 주도록 처리돼 있습니다.

필요한 도구 (npm 패키지에서 추출):

| 도구 | 출처 |
|---|---|
| `aapt2` | npm `aaptjs3` (리눅스용 실행파일) |
| `android.jar` | npm `@drxiaozhi/minapk` (API 34 스텁) |
| `d8.jar` | npm `@drxiaozhi/minapk` |
| `apksigner.jar` | npm `@drxiaozhi/minapk` |
| `ecj.jar` | npm `@drxiaozhi/minapk` (`ecj-3.45.0.jar`) |

> javac 대신 ecj를 쓰는 이유: 이 d8 빌드는 javac가 만든 클래스 중 내부/익명
> 클래스가 있는 것을 dex로 변환하다 죽습니다(`NullPointerException`). 같은 소스를
> ecj로 컴파일하면 정상 동작해요.
